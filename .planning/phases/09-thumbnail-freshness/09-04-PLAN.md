## The change, decided — not an open question

`PostThumbnail` splits into two files across the server/client boundary:

| File | Kind | Holds | Receives |
|------|------|-------|----------|
| `components/PostThumbnail.tsx` | **Server Component** (no client directive) | the no-thumbnail guard, the file-vs-external resolution | `{ post: Post, variant }` — unchanged call-site signature |
| `components/PostThumbnailImage.tsx` | **Client Component** (new) | `failed` state, `onError`, the wrapper div, `<Image>`, the `ImageOff` placeholder | `{ src: string, alt: string, variant: "card" \| "hero" }` |

A Server Component's props are never serialised into the flight payload — only its rendered output is,
and its rendered output here is three primitives. That is the entire fix.

**This repo already does exactly this, one directory over.** `components/comments/CommentSection.tsx` is a
Client Component whose props are `{ postId: string; postTitle: string }`, not `{ post: Post }` — which is
why the post page carries exactly one presigned URL (the hero's) and not two. The pattern being introduced
here is the pattern the codebase already established; `PostThumbnail` is the outlier.

## Why the four call sites do not change

The UAT gap's `missing` list item 2 reads "Update all four default-template call sites to the narrowed
interface." That was written from the diagnosis, before the fix's shape was chosen, and it assumed the
narrowing would happen *at* the call sites. It happens one level in instead, and the call sites are
correct as they stand:

- All four (`HomePage`, `SearchPage`, `CategoryPage`, `PostPage` in `templates/default/`) are **Server
  Components** — verified: none carries a client directive. Passing `post` from a Server Component to a
  Server Component is not a serialisation boundary and leaks nothing.
- Narrowing at the call sites would fork the file-vs-external resolution into four copies, directly against
  **D-02** ("extract the shared thumbnail rendering into one component… the resolution path, the failure
  placeholder and the external-URL branch land in one place instead of four").

So item 2 is satisfied by the call sites needing no change — but only for as long as they stay Server
Components. That is not a free-floating assumption: **Task 1 gates it with a source assertion**, and the
assertion is the durable form of the gap's item 2. Recorded here rather than left implicit, because a
future reader comparing the gap's `missing` list against the diff will otherwise see an unaddressed item.

## What this plan deliberately does not touch

- **The `terminal` template.** `templates/terminal/PostPage.tsx:70-80` is itself a Client Component and
  renders `post.thumbnail` straight into an `<img src>` — strictly worse than the payload-only case being
  fixed here. It is **not changed**, per **D-03** and REQUIREMENTS.md's Out of Scope table, and because
  `site.config.ts` sets `template: "default"`: the terminal components are never rendered on the deployed
  site, so they contribute nothing to the HTML this plan measures and cannot make the measurement fail.
  09-REVIEW.md INFO-02 already records the finding; Task 3 carries it into Tier 4 so a future terminal
  parity phase inherits it instead of rediscovering it.
- **The D-06 wording correction** (09-02-SUMMARY Finding B — `s-maxage` is not observable on the deployed
  response). A separate open item, not part of G-09-1, and not in this plan's file scope.
- **The other two `behavior_unverified_items`** in 09-VERIFICATION.md (host-allowlist guard, IMG-05 live
  half). UAT tests 2 and 3 accepted both as source-verified; reconciling them belongs to
  `/gsd-verify-work` on resume, not here.
