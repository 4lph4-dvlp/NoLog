# Phase 9 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Scope

This phase's entire user-visible surface is **one failure placeholder**. Everything else it does — the
`/api/thumbnail/[id]` proxy route, the uncached `getPost()` lookup, the second `NologClient` instance — is
invisible when it works. Per the scope warning: a working thumbnail must render **pixel-identically to today**
(IMG-05), and consolidating the three identical 96px card blocks (D-02) must read in the diff as a
de-duplication, not a redesign.

**The one genuine design decision (D-09/D-10):** when a thumbnail fails to load, the existing `bg-surface`
grey box gains a **centred icon** from `lucide-react`, detected client-side via `next/image`'s `onError`. No
caption text. This contract pins: which icon, what size at each of the two card shapes, what colour token, and
how it sits inside the existing wrappers.

**Explicitly out of scope, not specified here:**
- Any change to how a *working* thumbnail renders — same wrapper classes, same `object-cover`, same `sizes`.
- The proxy route, its cache headers, the uncached lookup, the hostname/redirect/content-type guards — no
  user-visible surface (IMG-03's rejections surface only as a native image-load failure → the same placeholder
  this contract specifies, never as separate UI copy).
- Loading/skeleton states — none exist today, none are added.
- The `terminal` template (D-03) and the email digest (D-04) — unchanged.
- `PostUnavailable.tsx` or the CONT-05 sentences — Phases 7/8, shipped and unchanged. (This document reuses
  their approved Design System/Spacing/Color/Typography baseline rather than re-deriving it.)
- Sidebars, layout, reading width — Phase 10.

## Spacing Scale

Confirmed 8-point scale, identical to Phases 7/8's baseline:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline padding |
| sm | 8px | Compact element spacing |
| md | 16px | Default element spacing |
| lg | 24px | Section padding |
| xl | 32px | Layout gaps |
| 2xl | 48px | Major section breaks |
| 3xl | 64px | Page-level spacing |

**Applied to this phase's one new visual element** (the failure icon, inside the existing wrapper — no wrapper
padding/margin changes):

| Surface | Wrapper (unchanged) | Icon size | Token |
|---------|---------------------|-----------|-------|
| 96px card (`HomePage`/`SearchPage`/`CategoryPage`) | `w-24 h-24` (96px, unchanged) | `w-8 h-8` (32px) | `xl` |
| Hero (`PostPage`, `aspect-video`) | `w-full aspect-video` (unchanged) | `w-12 h-12` (48px) | `2xl` |

Rationale: the hero is a larger, more prominent surface (full content-column width) than the fixed 96px card,
so it earns the next token up — mirroring the same "bigger surface, bigger icon" relationship Phase 7's
`PostUnavailable` establishes at its own (much larger) card scale. Both sizes are plain Tailwind width/height
utilities on the icon itself, not new spacing primitives — no new token introduced.

Exceptions: none.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | not applicable — no new actionable element this phase |
| Empty state (no thumbnail data at all — `post.thumbnail === null`) | not applicable — pre-existing, unchanged behavior: the wrapper box does not render at all (`{post.thumbnail && (...)}` guard, preserved verbatim in the shared component). This is a *different* condition from the failure state below and carries no copy either way, today or after this phase. |
| Error state (thumbnail present but fails to load — IMG-04, D-09/D-10) | **No text.** The existing `bg-surface` box gains a centred `ImageOff` icon and nothing else — no heading, no caption, no retry link. Decorative: the reader already sees the post title immediately beside (card) or above (hero) the placeholder, so the icon needs no accessible name of its own to convey "no image here" in context. | Destructive confirmation | not applicable — no destructive action in this phase |

**Why icon-only is correct here (not a gap):** `09-CONTEXT.md` § Specific Ideas is explicit that the failure
state must read as "there is no image here," not "still loading" — that distinction is what the icon buys over
the bare grey rectangle that already exists today, and it is the entire reason IMG-04 asks for a placeholder at
all. A caption was explicitly declined (D-09): the 96px card has no room for one, and adding copy would reopen
a default-language question this milestone has no reason to open. This phase does not deviate from that lock.

## UI Considerations

Two elements declared, both classified `media` (author-supplied, per the propose-then-confirm rule — an
`<Image>` inside a sized, surfaced wrapper is unambiguously `media`, not `static-content`): **E1 Card
thumbnail** (the one shared component instance rendered at `HomePage`/`SearchPage`/`CategoryPage`, per D-02's
consolidation — three call sites, one behavior) and **E2 Hero thumbnail** (`PostPage`'s `aspect-video`
instance). Per the taxonomy, `media` raises exactly four categories: `empty`, `loading`, `error`, `populated`.

**Resolved (explicit) — lift into `must_haves.truths`:**

| # | Element | Category | Acceptance criterion |
|---|---------|----------|------------------------------------------|
| 1 | E1 Card thumbnail | error | When the `<Image>` fires `onError` (proxy non-200, optimizer failure, or a dropped connection), the wrapper's `<Image>` is replaced by a centred `ImageOff` icon (32px, `text-tertiary`) inside the same unchanged `bg-surface` box — never an empty box, never a broken-image browser icon. |
| 2 | E1 Card thumbnail | populated | A thumbnail that loads successfully renders with the exact wrapper classes and `<Image>` props already on `main` today (`relative shrink-0 w-24 h-24 rounded-md overflow-hidden bg-surface`, `fill className="object-cover" sizes="96px"`) — no visual change for the happy path, regardless of whether the resolved `src` is the new proxy path or an unchanged external URL. |
| 3 | E2 Hero thumbnail | error | Same `onError` → `ImageOff` swap as E1, sized 48px, inside the unchanged `relative w-full aspect-video rounded-xl overflow-hidden bg-surface mb-10` wrapper. |
| 4 | E2 Hero thumbnail | populated | A hero thumbnail that loads successfully renders with the exact wrapper classes and `<Image>` props already on `main` today (`fill className="object-cover" priority`, no `sizes`) — no visual change for the happy path. |

**Dismissed (reason required):**

| Element | Category | Reason |
|---------|----------|--------|
| E1 Card thumbnail | empty | `post.thumbnail === null` is a different, pre-existing condition from a load failure — the wrapper box does not render at all (`{post.thumbnail && (...)}`, preserved verbatim). Unchanged by this phase; not IMG-04's concern (IMG-04 is specifically about a thumbnail that "genuinely fails to load," i.e. one that exists but breaks). |
| E1 Card thumbnail | loading | No skeleton/spinner exists today and none is added — explicitly out of scope per the phase's scope warning. `next/image`'s own blur-up/native browser rendering is unchanged and untouched by this phase's diff. |
| E2 Hero thumbnail | empty | Same reasoning as E1 empty — `post.thumbnail === null` renders no box, unchanged, and is a distinct condition from IMG-04's failure state. |
| E2 Hero thumbnail | loading | Same reasoning as E1 loading — no loading state exists or is added. |

**Probe accounting (no silent drops).** The taxonomy raises 4 categories per `media` element × 2 elements = **8
applicable considerations**. All 8 are accounted for above: **4 resolved (explicit)**, **4 dismissed with
reasons**. No `unclassified` candidates (both elements matched `media` unambiguously). No consideration left
`unresolved`.

## Placement & Composition Notes

Not a template-default field, but load-bearing for the executor. The route path, exact component file
location/name, and internal resolution logic are Claude's Discretion per `09-CONTEXT.md` and `09-RESEARCH.md`
— what follows pins the **visual contract** those implementation choices must satisfy; the file path/name below
is a sensible default, not a lock.

- **Suggested component:** `apps/web/src/components/PostThumbnail.tsx` — a `"use client"` component (D-10's
  `onError` requires a client-side event handler; this is the accepted cost D-10 already names). Receives
  `post` data as a prop from its Server Component parent, matching this codebase's established client-island
  pattern (`ThemeToggle.tsx`, `subscribeSlot`) — it does not fetch or import anything secret-gated.
- **Props (illustrative shape):** `post: Post`, `variant: "card" | "hero"`. The variant switch selects the
  wrapper classes, the `<Image>` prop set (`sizes` vs. `priority`), and the icon size — everything else
  (state, `onError` handler, the icon markup) is shared.
- **Src resolution (IMG-05's visual guarantee):** `post.thumbnailType === "external"` uses `post.thumbnail`
  directly, unchanged from today — it never constructs a `/api/thumbnail/...` path. Only `post.thumbnailType
  === "file"` (or the legacy `null` case) routes through the new proxy. This branch is what keeps external
  thumbnails visually and structurally untouched, per IMG-05.
- **The four call sites' existing early-out is preserved exactly:** no thumbnail data
  (`!post.thumbnail`) renders nothing, matching today's `{post.thumbnail && (...)}` guard at all four sites —
  this phase does not turn "no thumbnail configured" into a placeholder-icon state; only a present-but-broken
  thumbnail does.
- **Illustrative markup** (not prescriptive on internal JSX structure — the token/size/color values above are
  the binding contract):

```tsx
"use client";
import { useState } from "react";
import Image from "next/image";
import { ImageOff } from "lucide-react";
import type { Post } from "@/types";

const WRAPPER = {
  card: "relative shrink-0 w-24 h-24 rounded-md overflow-hidden bg-surface",
  hero: "relative w-full aspect-video rounded-xl overflow-hidden bg-surface mb-10",
} as const;

const ICON_SIZE = { card: "w-8 h-8", hero: "w-12 h-12" } as const;

export function PostThumbnail({ post, variant }: { post: Post; variant: "card" | "hero" }) {
  const [failed, setFailed] = useState(false);
  if (!post.thumbnail) return null;

  const src =
    post.thumbnailType === "external"
      ? post.thumbnail
      : `/api/thumbnail/${post.id}`;

  return (
    <div className={WRAPPER[variant]}>
      {failed ? (
        <div className="absolute inset-0 flex items-center justify-center">
          <ImageOff className={`${ICON_SIZE[variant]} text-text-tertiary`} strokeWidth={1.5} />
        </div>
      ) : (
        <Image
          src={src}
          alt={post.title}
          fill
          className="object-cover"
          onError={() => setFailed(true)}
          {...(variant === "card" ? { sizes: "96px" } : { priority: true })}
        />
      )}
    </div>
  );
}
```

- **Integration at the four call sites:** each of `HomePage.tsx:38-46`, `SearchPage.tsx:56-64`,
  `CategoryPage.tsx:52-60` replaces its existing `{post.thumbnail && (<div>...<Image/></div>)}` block with
  `<PostThumbnail post={post} variant="card" />`, still inside the same surrounding `<Link href={...}
  className="flex gap-4">`. `PostPage.tsx:86-96` replaces its block with `<PostThumbnail post={post}
  variant="hero" />`, still inside the same `<header>`-adjacent position, unchanged.
- **How IMG-03's route guards reach this placeholder:** a rejected request to `/api/thumbnail/[id]` (bad id,
  off-allowlist host, upstream redirect, non-`image/*` content-type — none of them UI concerns) resolves to a
  non-200 HTTP response for the `<img>` element's `src`. The browser's native image-load failure is exactly
  what fires `onError`. No separate error copy or status-specific UI is ever shown for *why* the route
  refused — the reader only ever sees "no image here," identically regardless of cause. This is intentional:
  IMG-03's guards are a security/correctness contract, not a reader-facing one.
- **Nothing else on any of the four pages moves.** Card metadata (title, summary, category, tags, dates),
  the post header, the notion content area, and comments are all untouched — this phase's diff is contained
  to the thumbnail block at each of the four sites plus the two new files (`PostThumbnail.tsx`, the route).
