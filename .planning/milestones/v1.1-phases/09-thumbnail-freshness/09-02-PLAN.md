## What is honestly checkable right now, and what is not

`09-VALIDATION.md`'s Tier 2 table lists all four IMG-03 guards as "a `curl` each". That is optimistic, and
`09-RESEARCH.md`'s own requirement-to-test map is the more honest reading: the id guard is directly
curl-able; the host, redirect and content-type guards cannot be exercised against real Notion assets,
because doing so would require a Notion page whose thumbnail property resolves to an off-allowlist host, an
S3 object that answers with a redirect, or a Notion file property holding a non-image — none of which this
project can construct on demand.

This plan does not paper over that. It upgrades two of the three from source-assertion to observed, by
standing up a throwaway local origin under a temporary, immediately-reverted route edit (task 1) — the same
fault-injection-then-revert discipline Phase 8 Plan 03 already used and recorded. The host-allowlist guard
stays source-asserted (09-01 task 3 proved the file holds exactly the two `next.config.ts` hostnames and no
third), and the evidence document must say so in those words rather than implying it was exercised.
