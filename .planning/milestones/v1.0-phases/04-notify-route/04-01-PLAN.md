<objective>
Deliver the notify route end-to-end: an authenticated, fail-closed, cron-only
`GET /api/notify-subscribers` that finds every newly-public post, assembles one
compliant digest, sends it through a single Resend broadcast, and marks only the
posts that shipped.

**User story (MVP mode):** **As** the site operator, **I want to** have my
subscribers automatically receive one digest email about every post that went
public since the last check, **so that** I never have to announce a post by hand
and no subscriber ever misses one.

Purpose: this is the phase's load-bearing slice. Task 1 proves the whole path —
auth, config gate, Notion read, digest assembly, one broadcast, Notion write-back
— works end to end. Task 2 makes that path survive a bad post, a failed mark and
a large backlog.

Output: `apps/web/src/app/api/notify-subscribers/route.ts` (new),
`apps/web/src/site.config.ts` (`notify` block), `apps/web/src/lib/notion.ts`
(two pass-throughs).
</objective>

Module-scope helpers, above the handler:

- `safeCompare(a: string, b: string): boolean` — build both `Buffer`s, and when
  their byte lengths differ, call `timingSafeEqual(bufA, bufA)` to burn
  comparable time and discard the result before returning false; otherwise
  return `timingSafeEqual(bufA, bufB)`. A bare try/catch around the throwing
  call is wrong and must not be used: `timingSafeEqual` throws on a length
  mismatch, so catching that throw and returning false makes a wrong-length
  secret measurably faster than a right-length-wrong-content one, which is the
  exact side channel SEC-01 exists to close (04-RESEARCH.md Pattern 2).
- `escapeHtml(value: string): string` — replace `&`, `<`, `>`, `"` and `'` with
  their HTML entities. Every Notion-sourced string interpolated into the digest
  markup goes through it, so a post title containing an angle bracket cannot
  break the email's markup or inject structure into a subscriber's mail client.
- `buildSectionHtml(post: Post): string` — one digest section. Render the
  escaped title as the anchor text of a link to
  `${CONFIG.site.url without a trailing slash}/post/${post.id}`, the escaped
  summary below it, and nothing else. Text-only for now: this task emits no
  `img` element at all (the thumbnail branch is plan `04-02`'s slice, and D-05
  already fixes the no-thumbnail case as text-only). Inline styles only, no
  external stylesheet, no table layout — the digest is a plain list of sections,
  which is the ceiling REQUIREMENTS.md Out of Scope sets for v1.
- `buildFooterHtml(): string` — three lines, in this order and independent of
  how many sections precede it: the why-you-are-receiving-this sentence (D-07, a
  short direct one-liner naming `CONFIG.site.title`, no subscription date and no
  echoed address), the configured `CONFIG.notify.physicalAddress` (D-06), and a
  visible unsubscribe link whose `href` is the literal Resend merge tag
  `{{{RESEND_UNSUBSCRIBE_URL}}}`. Use the repo's `CONFIG.site.locale === "ko"`
  ternary idiom for the human-readable copy in all three lines.

  **D-08 is revised by this task, under D-08's own escape hatch.** D-08 planned
  to rely purely on Resend's automatic header injection and render no
  unsubscribe markup in the body, explicitly conditional on research confirming
  that behaviour. 04-RESEARCH.md Open Question 1 could not confirm it from any
  quotable official Resend page — only the suppression-list half is confirmed.
  Rendering the merge tag as a visible link satisfies NOTIFY-02 with certainty
  under either interpretation, costs one line in a footer that already needed
  two, and is strictly additive. Record this revision in the SUMMARY.
- `buildDigestHtml(sections: string[]): string` — a minimal HTML document
  wrapping the joined sections followed by the footer. No greeting and no intro
  paragraph above the first section (D-04).

The exported `GET(request: Request)` handler, in exactly this order:

1. **SEC-01, the literal first statement.** Read `process.env.CRON_SECRET` and
   `request.headers.get("authorization") ?? ""`. If the secret is unset, or
   `safeCompare(authHeader, "Bearer " + cronSecret)` is false, write exactly one
   `console.error` line reading `[Notify] Unauthorized cron request rejected.`
   — a fixed string with zero interpolation, so no secret value, no header
   content and no IP can ever reach the log (D-15 logs the fact, D-16 keeps the
   detail out) — and return `new Response(null, { status: 401 })`. A plain
   explicit 401, deliberately not the sibling route's hide-existence 404: this
   route's only legitimate callers are Vercel Cron and the operator, so there is
   no anonymous audience whose probing needs misdirecting (D-14). Do NOT latch
   this log the way the subscribe route latches its unconfigured line — every
   failed attempt against this route is signal, not noise (D-15). Nothing above
   this block may touch Notion or Resend (04-RESEARCH.md Pattern 1 /
   `.planning/research/ARCHITECTURE.md` Anti-Pattern 2).
2. **SEC-02 configuration gate.** Read `process.env.RESEND_API_KEY`,
   `process.env.RESEND_AUDIENCE_ID`, `CONFIG.notify.physicalAddress` and
   `CONFIG.notify.fromAddress`. If any is falsy or empty after trimming, return
   `Response.json({ ok: true, code: "unconfigured" }, { status: 200 })` before
   any Notion or Resend call. A missing physical address fails closed at exactly
   the same tier as a missing API key — never send a non-compliant email because
   a forker left one field blank (D-09).
3. **Query.** `await getUnemailedPublicPosts()` inside a try/catch. On success
   with a zero-length array, return `{ ok: true, code: "no_posts" }` at 200 with
   no send and no mark. On a thrown error, log
   `[Notify] Unemailed-post query failed: ${message}` using the repo's
   `error instanceof Error ? error.message : String(error)` extraction and
   return `{ ok: false, code: "query_failed" }` at 500 — a dead Notion path must
   never read as a healthy run.
4. **Assemble.** Map the returned posts through `buildSectionHtml` preserving
   array order exactly — no sort, no reverse, no de-duplication, because
   `getUnemailedPublicPosts()` already returns Notion `created_time` ascending
   and D-01 makes that the display order with zero extra sort logic.
5. **Send — exactly one call.** `getResend()`, then one
   `resend.broadcasts.create({ audienceId, from: CONFIG.notify.fromAddress,
   subject, html, send: true })`. The subject is count-based and generic per
   D-02, built from the section count and `CONFIG.site.title` through the locale
   ternary, with the same shape whether the count is 1 or many. There must be
   exactly one such call site in the module and it must not sit inside any loop:
   one broadcast covers the entire digest, never one per post and never one per
   subscriber (NOTIFY-03; the per-recipient transactional send API must not
   appear in this module at all). If the returned `error` is truthy, log
   `[Notify] Broadcast send failed: ${error.message}` and return
   `{ ok: false, code: "send_failed" }` at 500, having marked nothing.
6. **Mark, only after a clean send.** Loop the sent posts and
   `await markEmailed(post.id)` for each. Return
   `{ ok: true, code: "sent", count }` at 200.

Wrap nothing else in a catch-all that would swallow step 5's failure into a
success — a failed send and a successful send must stay distinguishable in both
the response body and the log.
