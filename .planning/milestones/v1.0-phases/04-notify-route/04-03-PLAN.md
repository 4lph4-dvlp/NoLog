**A — SC#3, rejection before any work (no credentials needed).**

  1. `curl -s -o /dev/null -w '%{http_code}\n' http://localhost:3000/api/notify-subscribers` → expect `401`.
  2. Repeat with `-H "Authorization: Bearer definitely-wrong"` → expect `401`.
  3. In the server console, confirm each rejection printed exactly the line
     `[Notify] Unauthorized cron request rejected.` and nothing else — no secret
     value, no header contents, no IP.
  4. Confirm the Resend dashboard shows no new activity and Notion shows no
     changed rows for these two requests.

**B — SC#6, both routes fail closed.**

  1. Restart the server with `RESEND_API_KEY` and `RESEND_AUDIENCE_ID` unset
     (`env -u RESEND_API_KEY -u RESEND_AUDIENCE_ID npm run start`).
  2. Authenticated GET → expect `200` and a body containing
     `"code":"unconfigured"`; confirm no Notion request and no Resend request
     happened.
  3. `curl -s -o /dev/null -w '%{http_code}\n' -X POST -H 'Content-Type: application/json' -d '{"email":"you@example.com"}' http://localhost:3000/api/subscribe`
     → expect `404` (Phase 3's contract, unchanged).
  4. Restart with the Resend variables set but `NOTIFY_PHYSICAL_ADDRESS`
     temporarily unset → authenticated GET must still return
     `"code":"unconfigured"` (D-09: a missing compliance address fails closed at
     the same tier as a missing API key). Restore the variable afterwards.

**C — SC#5, a failed send marks nothing.**

  1. Restore the address, stage **3 posts** in Notion with `status = public` and
     `emailed` unchecked.
  2. Restart with a deliberately invalid `RESEND_API_KEY` (e.g. `re_invalid`).
  3. Authenticated GET → expect `500` and a body containing
     `"code":"send_failed"`, plus a `[Notify] Broadcast send failed:` line.
  4. In Notion, confirm **all 3 posts still have `emailed` unchecked**.

**D — SC#1, SC#2, SC#4: the real send.**

  1. Restore the valid `RESEND_API_KEY`. Leave the 3 posts unemailed, and
     **clear the title of exactly one of them** so its section build fails
     (NOTIFY-04's scenario).
  2. Authenticated GET → expect `200` with `"code":"sent"`.
  3. Server console: confirm a `[Notify] Failed to build section for post ...`
     line for the malformed post, and no such line for the other two.
  4. **Resend dashboard → Broadcasts:** confirm exactly **one** broadcast was
     created for this run — not two, not three, and no entries under the
     transactional Emails log.
  5. **Your inbox:** confirm you received exactly **one** email, and check:
     - the subject is count-based and names the site title (D-02);
     - it lists the two well-formed posts, oldest first (D-01), each with title,
       summary and a link that opens the right post;
     - a post whose Notion thumbnail is a pasted external URL shows its image;
       a post whose thumbnail was uploaded into Notion shows **no** image at all
       rather than a broken one;
     - there is **no** greeting or intro paragraph above the first post (D-04);
     - the footer carries the why-you-are-receiving-this line (D-07), the
       physical mailing address (D-06), and a visible **unsubscribe link**.

     dashboard now shows that contact as unsubscribed. Also open the message's

     present. Report both results: the visible link is the mechanism this phase
     ships, and the header is the extra `04-RESEARCH.md` Open Question 1 could
     not confirm from docs.

     and the **malformed post does not** (SC#4's second half). Re-invoke the

     correct; report which you saw.
