  <action>
Add the focus-rescue-then-inert sequence to the single per-side collapse routine, so both the click path and
the resize path get it without duplication.

**Refs.** Hold a `useRef<HTMLElement | null>` per side for the panel `<aside>` and a
`useRef<HTMLButtonElement | null>` per side for its toggle button. The two toggle components must accept a
ref for their `<button>` — give each one a forwarded ref (or an equivalent `buttonRef` prop it attaches to
the button) and attach it in both the mounted and the placeholder branch so the handle exists in either.
Attach the panel refs to the two `<aside>` elements alongside their existing `id`.

**The shared sequence.** Factor the collapse-side-effects into one function, e.g.
`applyCollapse(side, collapsed, animate)`, called by BOTH `handleToggle` and the `matchMedia` `change`
handler. Order is load-bearing:

1. If `collapsed` equals the side's current rendered value, return immediately — no inert write, no focus
   move, no attribute write. This is the idempotency guarantee: a repeated event must never steal focus from
   wherever the reader has since moved it.
2. If and only if `collapsed` is true: synchronously read `document.activeElement` and test whether the
   panel ref's element `.contains(...)` it. If so, call `.focus()` on that side's toggle button ref FIRST.
   Do not use a `setTimeout`, a `requestAnimationFrame`, or an effect — the rescue must complete in the same
   tick, before step 3, or focus will be sitting inside an inert subtree.
3. Set or remove the native `inert` attribute on the panel element — `setAttribute("inert", "")` when
   collapsing, `removeAttribute("inert")` when expanding. Use the attribute directly on the DOM node via the
   ref rather than a React prop, so the write is synchronous and ordered relative to step 2. Do NOT use
   `display: none`, `visibility: hidden`, or a conditional unmount: any of those removes the box from the
   render tree and makes the in-flight `grid-template-columns` transition snap instead of animating.
   `inert` removes tab-order and accessibility-tree membership immediately, regardless of how long the
   visual transition takes, which is what makes A11Y-02 true from the first millisecond of the collapse.
4. Only when `animate` is true (the click path, and only when reduced motion does not match) add the
   transition attribute — this is plan 10-01 task 2's existing gate; move the call inside this function if it
   currently lives in `handleToggle`, keeping the behaviour identical.
5. Flip the `<html>` attribute via `setSidebarAttr` and update the rendered state, exactly as today.

`handleToggle` calls `applyCollapse(side, next, true)` and additionally writes the explicit preference; the
`change` handler calls `applyCollapse(side, event.matches, false)` for each side whose preference is still
`null` and writes nothing to storage. The resize path therefore gets steps 1-3 identically and skips step 4
entirely — that is D-11 and A11Y-03 composed, not two mechanisms.

**Initial mount.** In the mount effect, after reading each side's state from the `<html>` attribute, apply
`inert` to any side that starts collapsed, so a visitor who arrives below the threshold (or with a saved
collapsed preference) never has a phantom tab stop before their first interaction. Do not run the focus
rescue on mount — nothing has focus inside a panel yet, and a `.focus()` call during hydration would steal
focus from the document.

**Do not** move either toggle button inside a panel: both live in the pinned row, outside both `<aside>`
elements, which is what keeps a collapse from inerting its own re-expand control.
  </action>
