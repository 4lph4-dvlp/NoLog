<objective>
Make the digest's per-post thumbnail actually load in a subscriber's inbox.

**Vertical slice:** after this plan, a subscriber opening the digest hours after
it was sent sees the post images that can survive that wait, and sees clean
text-only sections for the ones that cannot — instead of a column of broken-image
icons. That is a real, user-visible capability the tracer did not have.

Purpose: `04-RESEARCH.md` Pitfall 1 found that Notion returns a **presigned S3
URL that expires one hour after the page is fetched** for any image uploaded
into Notion (`file`-type), versus a permanent URL for a pasted external link
(`external`-type). D-03 locks the raw `post.thumbnail` as the digest's image
source, but `getFileUrl()` collapses both cases into a bare string and discards
which branch it took. A once-daily digest is routinely opened well past that
hour, so the distinction has to come back before any image is embedded.

Output: `Post.thumbnailType` on the core model, a `getFileType()` extractor
beside the existing `getFileUrl()`, and the thumbnail branch in the digest
section builder.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Notion `files` property value → `img src` in an outbound email | A URL originating in the forker's Notion workspace is embedded in HTML that renders inside third-party mail clients. |
| Notion S3 host → subscriber's mail client (or its image proxy) | Neither Vercel nor this app serves the image bytes; the recipient's client fetches them directly. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04-08 | Tampering | `img src` built from `post.thumbnail` in `buildSectionHtml` (ASVS V5 Input Validation) | medium | mitigate | The value is emitted only after the `URL` constructor parses it and its `protocol` is `https:`, and the surrounding attribute text is `escapeHtml`-escaped, so a `javascript:`, `data:` or attribute-breaking value cannot reach a recipient's mail client. |
| T-04-09 | Information Disclosure | The recipient's mail client fetching a Notion-hosted image URL | low | accept | Only `external`-type URLs are ever embedded, which are already public links the forker chose to paste; Notion-hosted presigned URLs — the ones that would carry a signature in the query string into a third-party image proxy's logs — are never emitted at all, so the expiry fix closes this as a side effect. |
| T-04-10 | Repudiation | A silently broken thumbnail in a delivered digest | low | mitigate | The per-run downgrade log line makes the fact and the remedy visible to the operator, so a subscriber report is not the discovery channel. |
| T-04-SC | Tampering | npm/pip/cargo installs | high | accept | No package is installed in this plan; `04-RESEARCH.md` § Package Legitimacy Audit records that nothing crosses the install boundary this phase. |
</threat_model>
