<objective>
Establish, from the operator's own live systems, the two facts ROADMAP Phase 5 turns on — that the production Notion database has zero unemailed public posts, and what the deployed Vercel project's real Function maxDuration is — commit them as a durable record, and confirm-or-correct the notify route's batch-size default against the figure that was actually read rather than the one that was assumed.

**Phase goal (verbatim, ROADMAP.md Phase 5):** "The notify path goes live in production only after the backfill has been confirmed complete, so the very first cron tick never emails a new subscriber the entire back catalog."

Purpose: This plan produces the *precondition* half of OPS-01. Plan 05-02 (the go-live commit) is gated on the artifact this plan commits, so the backfill-before-cron ordering is enforced by wave structure and by a commit-ancestry gate rather than by developer discipline — which is the stated reason ROADMAP kept Phase 5 as its own phase at all.

Output: `.planning/phases/05-production-cutover/05-01-VERIFICATION.md` (commit 1 of D-04's sequence) and a confirmed-or-retuned `NOTIFY_BATCH_SIZE_DEFAULT`.

**Why this plan has no `type="tracer"` task:** the tracer for this phase is the scheduled path itself (Vercel Cron -> authenticated notify route -> Notion -> Resend), and it lives in Plan 05-02 Task 2. It structurally *cannot* lead the phase: OPS-01 exists precisely to forbid that slice from being wired before the precondition this plan establishes is confirmed. Everything here is precondition work for that one slice.
</objective>
