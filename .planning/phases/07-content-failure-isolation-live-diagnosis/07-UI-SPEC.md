# Phase 7 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Scope

This phase's user-visible surface is deliberately tiny — one new state, one confirmed no-op. This is NOT a redesign. Per `07-CONTEXT.md`'s `<scope_warning>`:

1. **New "temporarily unavailable" state on `/post/[id]`** (CONT-04/SC#4, D-12) — the one genuine design decision this phase makes. Specified in full below.
2. **Chrome degradation (categories / related-posts) stays silent** (D-13, CONT-04) — confirmed below to need **zero** new UI. `DefaultPostPageProps` (`apps/web/src/templates/default/PostPage.tsx:9-14`) accepts only `post` and `recordMap`; `categories`/`relatedPosts` are fetched but never rendered under the active `default` template. A fetch failure there already degrades to an unrendered `[]`, matching `apps/web/src/app/layout.tsx:46-53`'s existing precedent. No visual work required.

**Explicitly out of scope, not specified here** (see `07-CONTEXT.md`/`REQUIREMENTS.md` for the authoritative list): the existing `"Content could not be loaded."` string (D-14, untouched — CONT-05/Phase 8 owns splitting it); any `error.tsx` (D-16, declined); the `terminal` template (inactive, `site.config.ts:11`); sidebar/layout/reading-width work (Phase 10); thumbnails (Phase 9); the D-06 debug route (operator-only, secret-gated, returns data — no UI).

**Open dependency this UI-SPEC does not resolve:** `07-RESEARCH.md`'s Open Question 1 — because `NologClient.getPost()` (`packages/core/src/client.ts:311-338`) already swallows every failure to `null` and cannot be modified (published package), reaching this new state at all requires the planner to add an app-level discriminating check before `notFound()`. That is an engineering decision, not a design one. **This contract specifies what renders if/when that discriminator fires.** If the planner instead accepts the residual gap (no discriminator added), this component is written but never reached — record that explicitly in the phase's verification notes rather than silently dropping the component.

## Copywriting Contract

**Copy language decision:** English only, unlocalized — no `CONFIG.site.locale === "ko"` branching in this new component. Per `07-CONTEXT.md`'s design-system note, this follows the one existing precedent for reader-facing fallback copy (`"Content could not be loaded."` in `DefaultPostPage.tsx:100`, which is hardcoded English regardless of locale) rather than the bilingual pattern used by the page's date/author labels. This is a deliberate scope-minimizing choice, not an oversight — do not add locale plumbing to this component.

| Element | Copy |
|---------|------|
| Heading | "This post is temporarily unavailable" |
| Body | "We couldn't load this post from Notion right now. This is usually temporary — please check back in a few minutes." |
| Primary link (not a CTA button — a way back, not an action) | "Back to feed" — reuses the exact existing string and icon (`ArrowLeft`, `w-4 h-4`) from `DefaultPostPage.tsx:19-25`, unlocalized per the decision above |
| Empty state | Not applicable this phase — see "Scope" above; the content-empty-vs-fetch-failed wording split is CONT-05/Phase 8 (D-14), explicitly deferred |
| Error state (this phase's actual new state) | Heading + body above. No retry button — a manual retry control is CONT-F01, deferred to v2; the body copy's "check back in a few minutes" phrasing is the only retry affordance this phase ships |
| Destructive confirmation | Not applicable — this phase introduces no destructive actions |

**HTTP status (resolved, Claude's Discretion per `07-CONTEXT.md`):** This state renders as a normal `200` response — no `notFound()` call, no custom status code. Rationale: (1) matches D-13's "silent degrade, log-only" philosophy already established elsewhere in this phase; (2) a Next.js Page (not a Route Handler) cannot easily emit a non-200/404/redirect status without disproportionate new plumbing for a narrow, temporary surface; (3) the diagnostic value this phase is actually built to deliver (CONT-01/CONT-02) lives entirely in the server log payload and the debug route, not in what status code the reader's browser receives. If the planner has a stronger reason to prefer `503`, record that override explicitly in the plan rather than silently deviating from this default.

## Placement & Composition Notes

Not a template-default field, but load-bearing for the planner/executor:

- **Where it renders:** returned directly from `apps/web/src/app/post/[id]/page.tsx`'s default export, in place of the current unconditional `notFound()` call, when the discriminator (if added — see "Scope" above) judges the failure transient. It still renders **inside** the full page chrome — `app/layout.tsx` wraps every route's `children` in `DefaultLayout`/`TerminalLayout` (confirmed: sidebars, search, profile, theme toggle, header all stay present; only the center-column content changes).
- **Suggested (non-binding) file location:** `apps/web/src/components/PostUnavailable.tsx` — a standalone, template-agnostic component (not `templates/default/*`), since it does not vary by `CONFIG.template` and needs no `post` data (unlike `DefaultPostPage`, which requires one). It uses only base `globals.css` tokens available site-wide, so it renders reasonably under either template; visual parity with the `terminal` CLI aesthetic is out of scope (tracked as `TMPL-F01`, deferred).
- **Container width:** matches a normal post's horizontal rhythm — `max-w-none mx-auto py-8 md:px-4`, identical to `DefaultPostPage.tsx:16`'s outer `<article>` wrapper — so navigating into this state doesn't visibly jump the content column width.
- **Suggested markup shape** (illustrative, not prescriptive on JSX structure — the token/copy/spacing values above are the binding contract):

```tsx
<div className="max-w-none mx-auto py-8 md:px-4">
  <div className="flex flex-col items-center justify-center text-center gap-4 py-16 px-6 rounded-xl border border-border bg-surface">
    <CloudOff className="w-10 h-10 text-warning" strokeWidth={1.5} />
    <h1 className="text-2xl font-semibold text-text-primary">
      This post is temporarily unavailable
    </h1>
    <p className="max-w-md text-text-secondary text-base">
      We couldn&apos;t load this post from Notion right now. This is usually
      temporary — please check back in a few minutes.
    </p>
    <Link
      href="/"
      className="inline-flex items-center gap-1 text-sm text-accent hover:text-accent-hover transition-colors mt-2"
    >
      <ArrowLeft className="w-4 h-4" />
      Back to feed
    </Link>
  </div>
</div>
```

- **Distinctness from `notFound()` (the SC#4 requirement this exists to satisfy):** today, `notFound()` with no custom `not-found.tsx` anywhere in the app renders Next.js's generic built-in 404 content inside the same layout shell — unbranded, no icon, no site tokens. The card above is immediately distinguishable by sight: bordered/surfaced card, warning-toned icon, and copy that names the actual cause ("temporarily unavailable" / "couldn't load ... from Notion") rather than Next's generic "page could not be found."
